# 工作流编辑页 copilot 测试用例（测试工程师参考）

## 依据与范围

- 已确认规格：[spec.md](./spec.md)，2026-11-23 用户确认版（提交 6af2ee7d58 中的修订）。
- 设计复查：design.md 2026-11-23 用户确认版（含 codex 审查修订）。用例的入口、造数、观察方法已按设计更新，受影响的用例为 TC-CPL-005、TC-CPL-008、TC-CPL-012、TC-CPL-016。
- 目标版本与构建：v3.1.0-beta1 / 分支 `feat/v3.1.0-beta1/007-workflow-copilot`，尚无构建（待实现）。
- 其他依据：F005、F006 规格（声明编译、`bisheng flow diff` 的差异口径）。
- 代码核对：基于 `94493ef494` 核对了既有入口，包括：
  - 编辑页 `pages/BuildPage/flow/Panne.tsx`、`FlowChat/ChatTest.tsx`；
  - 撤销 `util/hook.ts` `useUndoRedo`；
  - 权限 `api/services/flow.py` `judge_flow_write_permission`；
  - 默认模型 `llm/domain/services/llm.py` `aget_workflow_llm_with_meta`；
  - 代码节点开关 `WorkflowConf.code_node_enabled`。

  copilot 本身尚未实现，相关行为按规格推导。
- 覆盖范围：
  - 生成与修改主链路、差异预览与应用 / 撤销；
  - 编辑权限、资源权限范围、默认模型缺失、代码节点开关；
  - 便签保留、发送后改画布的覆盖确认、停止、失败恢复、密钥不外泄；
  - CLI 导出往返。

  不覆盖模型输出质量本身（同一需求每次输出可能不同），只判定系统对输出的处理是否符合规则。

## 环境、账号与测试数据

| 代号 | 角色或数据 | 准备方法 | 确认方式或待确认项 |
| --- | --- | --- | --- |
| ENV | 隔离环境 | 按 design §7 端到端步骤起 `_probe/e2e/` 基础设施、本分支后端 / worker / 前端 | 浏览器能打开工作流编辑页 |
| MDL | 工作流默认模型 | 管理员在「系统模型配置 → 工作流」设置一个已上线的大模型 | 待研发确认：具体用哪个模型服务（需用户授权） |
| U-EDIT | 有编辑权限的用户 | 创建工作流 WF-A 的用户本人 | 能在编辑页修改并保存 WF-A |
| U-VIEW | 只有查看权限的用户 | 给该用户 WF-A 的「可使用」而非「可编辑」权限 | 打开 WF-A 时不能保存 |
| KB-1 / KB-2 | 知识库 | U-EDIT 能用「研报库」；另建同名「研报库」但只授权给别人 | U-EDIT 的知识库选择框里只出现一个「研报库」 |
| WF-A | 已有工作流 | 开始 → 对话输入 → 大模型 → 输出，外加一条便签「勿删」 | 画布上可见便签 |
| WF-EMPTY | 空工作流 | 新建工作流，只有开始节点 | — |
