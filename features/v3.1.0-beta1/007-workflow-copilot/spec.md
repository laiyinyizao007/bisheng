# 工作流编辑页 copilot（自然语言生成与修改工作流）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里，How 的唯一真相在 [design.md](./design.md) 与 [tasks.md](./tasks.md)。

**版本**：v3.1.0-beta1。**优先级**：P1。**状态**：2026-11-23 用户已确认（含 codex 审查后的修订）。

**关联需求**：本会话已确认的 Spec Discovery 决策——
- **入口**：工作流编辑页画布右侧抽屉，输入区复用 `@bisheng/chat` 的会话输入组件。
- **落画布**：先看差异，点「应用」才替换画布；可撤销，不自动保存。
- **模型**：复用「工作流默认模型」。
- **知识来源**：复用 F006 的「工作流声明」技能包。
- **资源**：模型、知识库、工具能唯一确定就自动填（只在当前用户有权使用的范围内），否则留空并在差异预览里标出。
- **对话记录**：只在本次打开编辑页期间保留。

**依赖**：
- F005-workflow-as-code：节点模板后端化、工作流声明的编译与校验规则。
- F006-flow-yaml-skill：「工作流声明」技能包。
- 发版线既有能力：系统模型配置中的「工作流默认模型」、F048 资源授权、工作流编辑页（画布、撤销 / 重做、测试运行面板）、`@bisheng/chat` 会话输入组件。

> **范围边界**
>
> - **本次纳入**：
>   - **编辑页 copilot 抽屉**：在工作流编辑页用自然语言描述需求，得到一份工作流方案。
>   - **两种模式**：画布为空时生成整条工作流；画布已有内容时在当前画布基础上修改。
>   - **差异预览与应用**：方案以「相对当前画布的差异」呈现，用户点「应用」才落到画布，可撤销。
>   - **资源自动匹配**：在当前用户有权使用的范围内为方案填模型、知识库、工具。
>   - **画布与声明的双向转换**：让 copilot 能读懂现有画布、也让方案能落回画布。命令行一侧同样受益（可把线上工作流导出成声明）。
> - **本次明确排除**：
>   - **替用户保存、上线、运行工作流**：应用只改画布。保存、上线、试运行仍是用户自己的动作，规则不变。
>   - **对话记录的持久化与共享**：不新增存储。刷新或离开编辑页即清空；同一工作流的其他协作者看不到。
>   - **自选模型**：copilot 固定使用「工作流默认模型」，不在抽屉里提供模型切换。
>   - **超出用户权限的资源**：方案里不会出现用户无权使用的模型、知识库、工具，即使用户在对话里直接给出了它的 id。
>   - **工作流运行时语义的变更**：节点行为、校验规则均不改；copilot 只产出平台本来就接受的工作流。
>   - **代码节点开关的绕过**：平台关闭代码节点时，copilot 不产出代码节点。
>   - **助手、技能等其他应用类型的 copilot**：本期只做工作流编辑页。

> **[待澄清]（design 阶段定，需用户确认）**：AC-23 要求平台与 CLI 用同一套编译 / 校验规则，而 release-contract 表 1 现把「声明编译」划在 F005 的 CLI 侧、平台后端无法直接使用。满足 AC-23 需要调整这一归属（例如让平台与 CLI 共用同一份编译实现），具体方式及对 release-contract F005 行的改动在 design.md 中提出，经用户确认后同步修订契约。

## 1. 用户故事

作为 **工作流搭建者**，
我希望 **在编辑页里用一句话描述要什么样的工作流，直接得到一份能用的画布**，
以便 **不必先熟悉 12 类节点的每个参数，就能搭出第一版**。

作为 **工作流维护者**，
我希望 **用自然语言对现有工作流提修改（加一个节点、改一个分支条件），并在落画布前看清到底改了什么**，
以便 **放心让 AI 动手，而不担心它悄悄改坏我没提到的部分**。

## 2. 验收标准

### 2.1 入口与可用性

- **AC-01** — WHEN 对当前工作流有编辑权限的用户打开工作流编辑页, THE SYSTEM SHALL 提供 copilot 入口；打开后在画布右侧显示抽屉，输入区为 `@bisheng/chat` 的会话输入组件。
- **AC-02** — WHILE copilot 抽屉打开, WHEN 用户打开测试运行面板, THE SYSTEM SHALL 收起 copilot 抽屉；反之打开 copilot 抽屉时收起测试运行面板。收起抽屉不清空对话。
- **AC-03** — IF 当前租户未配置「工作流默认模型」，或该模型已被删除或停用, THEN THE SYSTEM SHALL 在抽屉内显示是哪一种情况（未配置 / 模型不可用）及「请管理员在系统模型配置中设置」的指引，并禁用发送，不发起生成请求。
- **AC-04** — IF 发起生成请求的用户对该工作流没有编辑权限（包括绕过页面直接调用）, THEN THE SYSTEM SHALL 拒绝请求并返回无权限错误，不调用模型。

### 2.2 生成与修改

- **AC-05** — WHEN 画布上只有开始节点或没有节点时用户发送需求, THE SYSTEM SHALL 返回一份完整工作流方案（含开始节点，且每条路径都能走到结束或等待输入）。
- **AC-06** — WHEN 画布已有内容时用户发送需求, THE SYSTEM SHALL 以**发送那一刻的画布**（含尚未保存的手动改动）为基础返回修改方案。
- **AC-07** — THE SYSTEM SHALL 在同一次打开期间把此前的对话作为后续轮次的上下文；每一轮的修改基础仍是发送时的画布，而不是上一轮的方案。
- **AC-08** — THE SYSTEM SHALL 保持用户需求未涉及的画布内容不变：未改动节点的 id、参数、位置不变；copilot 无法表达的内容（便签、报告模板引用、未识别字段等）原样保留。
- **AC-09** — THE SYSTEM SHALL 为方案中新增的节点给出不与现有节点重叠的位置。
- **AC-10** — THE SYSTEM SHALL 只把能通过工作流声明编译校验（与 `bisheng flow compile` 同一套规则）的方案交给用户；IF 最终仍未通过校验, THEN THE SYSTEM SHALL 不提供「应用」，并列出每个问题涉及的节点名与原因（例如「节点『摘要』缺少用户提示词」），不展示原始报错堆栈。
- **AC-27** — IF 生成过程中模型调用失败、超时或连接中断, THEN THE SYSTEM SHALL 在对话中显示本轮失败及可读原因（不含密钥与连接信息），不产出方案、画布不变，用户可直接重新发送。
- **AC-11** — WHILE 方案生成中, THE SYSTEM SHALL 在输入区显示停止按钮；WHEN 用户点击停止, THE SYSTEM SHALL 终止本轮，不产出方案，画布不变。
- **AC-12** — WHERE 平台关闭了代码节点, THE SYSTEM SHALL 不在方案中产出代码节点；用户明确要求代码节点时，回复说明该能力已被平台关闭。
- **AC-13** — WHEN 用户的消息不是对工作流的生成或修改请求（例如提问某个节点怎么用）, THE SYSTEM SHALL 只回复文字，不产出方案。

### 2.3 资源填写

- **AC-14** — THE SYSTEM SHALL 把方案中需要模型的节点默认填为「工作流默认模型」；用户在需求里点名的模型若能在其可用模型中唯一匹配，则填该模型；无匹配或多个候选时留空，并在差异预览里把该处标为「需要你选」。
- **AC-15** — WHEN 方案需要知识库或工具, THE SYSTEM SHALL 只在当前用户有权使用的范围内按名称匹配；唯一匹配则填入，无匹配或多个候选则留空，并在差异预览里把该处标为「需要你选」。
- **AC-16** — IF 方案（无论来自模型输出还是用户输入）引用了当前用户无权使用或不存在的资源, THEN THE SYSTEM SHALL 把该处清空并标为「需要你选」，不把该资源 id 带进方案。

### 2.4 差异预览与应用

- **AC-17** — WHEN 方案生成完成, THE SYSTEM SHALL 以相对发送时画布的差异呈现方案：新增 / 删除的节点、改动的节点及其改动的参数（旧值 → 新值）、新增 / 删除的连线；未改动的内容不逐项列出。
- **AC-18** — WHEN 用户点击「应用」, THE SYSTEM SHALL 把差异预览中列出的改动落到画布（其余内容按 AC-08 保持不变），且一次撤销（Ctrl+Z）即可恢复到应用前的画布；应用不触发保存。
- **AC-19** — IF 用户在发送之后、点击「应用」之前又手动改了画布, THEN THE SYSTEM SHALL 在应用前弹出确认，说明「发送后你在画布上的改动会被覆盖」；用户确认才应用，取消则画布不变（用户可另行基于新画布重新发送）。不得静默丢弃这些改动。
- **AC-20** — WHEN 用户不应用方案（忽略、关闭抽屉或发起新一轮）, THE SYSTEM SHALL 保持画布不变。

### 2.5 对话记录

- **AC-21** — THE SYSTEM SHALL 在编辑页保持打开期间保留对话（含收起再打开抽屉）；WHEN 用户刷新页面或离开编辑页, THE SYSTEM SHALL 清空对话；平台不保存对话内容。

### 2.6 知识来源与一致性

- **AC-22** — THE SYSTEM SHALL 以 F006「工作流声明」技能包作为 copilot 了解节点类型、参数与写法的唯一来源；技能包随节点模板更新后，copilot 无需单独改动即可使用新参数。
- **AC-23** — THE SYSTEM SHALL 保证同一份工作流声明在 copilot 与 `bisheng flow compile` 中得到相同的校验结论与相同的画布结构；编译或校验规则只改一处，两边同时生效（对同一组样例声明，两边结论逐条一致）。
- **AC-24** — WHEN 用户在命令行对一条已有工作流执行导出, THE SYSTEM SHALL 输出一份可再次编译的工作流声明，对导出结果再编译得到的画布与原画布在 `bisheng flow diff` 意义下无差异；声明无法表达的内容（便签、画布视角、未识别字段）不进入导出结果，THE SYSTEM SHALL 在导出时逐项列出被略过的内容。

### 2.7 安全

- **AC-25** — THE SYSTEM SHALL 不在日志、错误信息、对话或差异预览中输出以下内容的原文：模型服务的 API 密钥与访问地址中的凭据、工具的鉴权配置（API Key、Bearer 令牌、Basic 密码）、平台访问令牌；日志记录请求时不记录画布与对话全文。
- **AC-26** — WHERE 多租户开启, THE SYSTEM SHALL 使用当前租户（含继承）的「工作流默认模型」，资源匹配只在当前租户内进行。

## 3. 边界情况

- 当模型输出无法解析为工作流声明时，系统应视为一次未通过校验（AC-10），而不是把原始输出落到画布。
- 当用户的需求很模糊（例如「做个工作流」），系统可以只回复文字追问，不强行产出方案（AC-13）。
- 当画布很大时，系统应仍以完整画布为修改基础；若超出模型可处理的长度，应明确告知用户，而不是只基于部分画布产出方案。
- 当方案删除了用户需求没提到的节点时，差异预览必须把它列为「删除」（AC-17），由用户决定是否应用。
- 当工作流处于上线状态时，copilot 照常可用；保存是否允许沿用既有规则（上线中不可保存），copilot 不改变它。
- 当两位协作者同时编辑同一工作流时，copilot 只作用于本人当前的画布，不涉及他人的未保存内容。
