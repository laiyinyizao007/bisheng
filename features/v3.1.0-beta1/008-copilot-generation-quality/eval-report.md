# F008 评测报告

> 评测方法见 [design.md §6](./design.md)；原始结果在 `src/backend/test/workflow/copilot/eval/results/`。
> 门槛（spec AC-11）：「应先问」组命中率 ≥ 80%；「应直接做」组误问率 ≤ 20%；「做不到」组明确说明 ≥ 75%；结构校验通过率不低于基线。

## 基线（方案 A 之前，F007 当前版本）

- 运行：`20261125-042045-baseline`（run_id `5a34e8`），18 条 × 3 次 = 54 次，模型调用 147 次，用时 848 秒，0 次运行错误。
- 环境：隔离环境独立 API（17870，代码为 F007 + 自动布局 + 租户修复的本地集成分支），工作流默认模型 MiniMax-M3；评判模型 MiniMax-M3，3 条校准项全部判对。
- **剔除 `cannot-code-node`**：该环境的系统配置开着代码节点（`workflow.code_node_enabled: true`），用例的前提不成立，3 次结果无效。此后用例加了 `requires: {code_node_enabled: false}`，前提不成立时自动跳过并记入结果。下表为剔除后按同一套统计重算（51 次）。

**观察**

1. 现状从不先问：「应先问」组 15 次全部直接出方案（命中率 0%），硬性要求只有 40%（例如阈值写成 `greater_than`、没用发送邮件工具），走查 56%。
2. 「做不到」只有一半说明了：审批说明了（3/3），数据库写入一次都没说明（0/3），定时触发 2/3。
3. **工具参数名靠猜**：`clear-calculator` 3 次全部失败——三次尝试都把计算器的参数写成 `input`，平台校验「模板里没有参数 input」。原因是提示词的资源清单只给了工具名、没给参数名；已在方案 A（T005）里补上。
4. 修改已有画布表现稳定（全部 100%）。

**未达标原因**

- 命中率：4 次未命中里 3 次是模型没问边界、自己把「≥ 1000 也打折」「18 岁算成年」写进了「假设」；1 次只问了审批、没问币种。
- 结构：3 次失败都在「做不到」组——2 次是澄清后的第二轮推理超过 4 万字、超过单次 180 秒被截断；1 次只用文字说明做不到，既没问也没给方案。
- 评测自身的两处修正：`clear-calculator` 的前提不成立（预置计算器工具没有参数，模型改用 Agent 调用计算器反而是对的），停用并改用 `clear-web-reader`。

**用户决定（AC-11）**：继续调方案 A。调整见 design.md 修订历史最后一条。
