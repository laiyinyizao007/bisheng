# 工作流声明写法技能包

**版本**：v3.1.0-beta1。**流程档位**：小功能（SDD-Guide §1：单模块、不新增跨特性契约）。**状态**：2026-11-23 用户已确认（包名 `workflow-as-code`；「AI 能否一次写对」只做一次人工演示）。

**关联**：[F005 工作流即代码](../005-workflow-as-code/spec.md)提供 `bisheng flow` 命令族与 YAML 声明；[F053 开发者技能包](../../v3.0.0/053-dev-cli-skills/spec.md)提供 `bisheng skills sync` 的分发与接入机制。本特性在两者之上补一份技能包，不改动它们的契约。

## 1 目标与范围

作为**用自然语言描述需求的开发者**，我希望本机的 AI 编程助手读完一份平台随附的说明，就能把「我想要一个什么样的工作流」写成能通过 `bisheng flow compile` 的 `flow.yaml`，并走完推送与运行，而不必去翻平台源码和测试。

作为**平台维护者**，我希望这份说明与节点模板、编译器、校验器保持同源：节点模板或校验规则一变，说明没跟上就在测试里变红，而不是让 AI 照着过期的写法自信地写错。

**本期做**：新增技能包「工作流声明」（包名 `workflow-as-code`），随平台分发，`skills sync` 默认同步并接入本机 AI 编程工具。

**本期不做**：
- 平台内的「自然语言生成工作流」入口（不调用大模型、不新增接口、不改前端）。
- `bisheng flow` 命令族的行为变更（命令、参数、退出码、输出形状均不动）。
- 节点模板与校验规则本身的变更。
- 替 AI 决定上线、绕过线上改动保护或代人确认（技能只能教「什么时候必须停下来问人」）。

## 2 验收标准

### 2.1 内容

- **AC-01** — THE SYSTEM SHALL 提供技能包 `workflow-as-code`，其 `SKILL.md` 带可被 AI 编程工具识别的头部（名称、触发描述），触发描述覆盖「用自然语言建 / 改毕昇工作流」「写 flow.yaml」「bisheng flow」等说法。
- **AC-02** — THE SYSTEM SHALL 在 `SKILL.md` 中为平台节点模板里的**全部 12 类节点**各给出一节，列出该类节点可在 `params` 中声明的参数键、含义、是否必填及取值形状；对需要 `tab` 的节点说明可选值。
- **AC-03** — THE SYSTEM SHALL 说明声明文件的顶层结构、节点与连线的可用字段，以及未知字段会被编译拒绝。
- **AC-04** — THE SYSTEM SHALL 说明变量引用写法 `{{#节点id.变量#}}`、可引用的变量从哪来，以及写错时的后果（编译期报错；绕过编译直接改线上时运行期静默不替换）。
- **AC-05** — THE SYSTEM SHALL 说明条件分支：`cases` 的写法、case `id` 即出边 `handle`、默认出口、`and`/`or` 逻辑、`value` 与 `ref` 二选一，并列出平台支持的全部比较符。
- **AC-06** — THE SYSTEM SHALL 说明工具节点：先用 `bisheng flow tool register` 注册 OpenAPI 描述、用 `tool list` 查操作标识、在声明里按操作标识引用，以及工具参数只能是字符串。
- **AC-07** — THE SYSTEM SHALL 给出从自然语言需求到运行结果的标准步骤：写声明 → `compile` → 按报错逐条修改 → `push --create` / `diff` / `push` → `run`（含无终端时的续跑写法），并说明每一步失败时看哪些字段。
- **AC-08** — THE SYSTEM SHALL 写明 AI 必须停下来交给人的情形：`diff` 报出线上独有内容时是否带 `--allow-drop-online-only`、需要真实模型 id 或密钥时、上线工作流；技能不得建议 AI 自行带上该参数或自行上线。
- **AC-09** — THE SYSTEM SHALL 随包附一个可直接编译通过的样例声明（含多轮输入、条件分支、大模型节点与外置提示词），供 AI 改造。

### 2.2 同源与防漂移

- **AC-10** — WHEN 平台节点模板新增、删除或改名节点类型或参数键，THE SYSTEM SHALL 使技能包的一致性测试失败，并指出是哪一类节点、哪个参数键没有对上；技能里写到的参数键必须真实存在于模板，模板中可声明的参数键也必须在技能里出现。
- **AC-11** — WHEN 编译器的可用字段、比较符或逻辑取值变化，THE SYSTEM SHALL 使一致性测试失败；技能列出的必填参数必须与校验器实际检查的必填参数一致。
- **AC-12** — THE SYSTEM SHALL 在测试中用平台自己的节点模板编译并校验随包样例，结果必须零问题；样例改坏（如引用不存在的节点）时测试必须报出该问题。

### 2.3 分发

- **AC-13** — WHEN 开发者运行 `bisheng skills sync` 或登录触发的自动同步，THE SYSTEM SHALL 在已有两个技能包之后同步 `workflow-as-code`，并像已有技能包一样接入本机 AI 编程工具；首次 `bisheng deploy` 写入项目 `AGENTS.md` 的指针同样包含它。
- **AC-14** — IF 平台版本早于本技能包（分发端点对它返回不存在），THEN THE SYSTEM SHALL 沿用既有行为把它报为跳过，不使整次同步失败，已有两个技能包照常同步。
- **AC-15** — THE SYSTEM SHALL 保持技能包的分发、按平台分目录、单向覆盖与接入方式不变；技能包源码 README 的目录说明同步更新。
- **AC-16** — WHEN CLI 代码因本特性变化，THE SYSTEM SHALL 重新打包平台随附的 CLI 安装包并更新清单校验值，使既有的安装包一致性检查通过。

## 3 明确接受的边界

- 技能内容是写给 AI 的说明，正确性靠 AC-10～AC-12 的结构性测试兜底；「AI 读完是否真能一次写对」只做一次人工演示，不设自动化评测。
- 参数的**含义**描述无法由测试校验，只校验键名、必填性与比较符集合；含义随模板改动可能过时，由改模板的人同步更新。
- 界面文案（节点与参数的显示名）仍归前端多语言文件；技能用参数键写作，不复制显示文案。
